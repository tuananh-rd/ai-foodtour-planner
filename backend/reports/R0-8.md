# R0-8 backend fixes

Author: Codex. Review requested: Claude; independent integration QA: Antigravity.
Base: `git merge foodtour-claude-coordinator` fast-forwarded to `7b03249`.

## Changes

- Unwrap `{ "venues": [...] }` for every configured JSON file. An empty list is valid; missing/non-list `venues` still fails without fallback.
- Identify synthetic provenance from an explicit wrapper marker (`synthetic: true` or a leading SYNTHETIC label) or a nonempty dataset with every input row marked boolean `synthetic: true`. Unmarked/mixed datasets remain private; individual synthetic rows retain their own marker. Neither filenames nor venue names establish provenance.
- Separate canonical/import field mapping from provenance. Canonical private files and synthetic import rows preserve their respective prices, tags and geo flags. Loader source is now `private` or `synthetic`, which flows through the existing API mapping; routes required no changes.
- Resolve relative `FOODTOUR_DATA_PATH` against the repository root, including `contracts/fixtures/venues.evidence.synthetic.json`; direct `load_dataset(path)` arguments still require absolute paths.
- Add varied synthetic rating/count, meal/audience, cuisine, amenities and source timestamps to the 13-row default fixture. Ratings use the normalized `rating` field with scale 5 so existing direct `Venue(**row)` fixture consumers remain compatible. Counts include 2/4, 24/120 and null. Unknown hours and estimated venue-range prices remain unchanged.
- User interests/exclusions use `fold_uncached`; only venue fields use cached `fold`. Faster whole-word phrase matching preserves tag boundaries, synonyms and Unicode behavior without caching user terms. No request-local cache was needed.
- Purge expired extraction entries under the lookup lock before checking for a hit, including misses followed by provider failure. Existing TTL and cache behavior remains covered.

## Existing expectations updated

Only `backend/tests/data/test_loader.py` changed existing expectations: a boolean-marked synthetic import row now has `venue.synthetic=True` and source `synthetic`; unmarked CSV source is `private` rather than `csv`; the invalid-shape case uses `{"venues": null}` because `{"venues": []}` is now supported. No planner/API expected stop IDs, coordinates, contract snapshots or legacy tests were changed.

## Limits

Private-data legacy compatibility cannot be validated here without that ignored input. No live DB/provider, frontend/browser or public deployment validation was performed. Extraction expiry is enforced during lookup/write activity, not by a background timer. Cross-review and independent integration QA remain with Claude/Antigravity; this change is not self-approved.
